## 跟做时的约定

所有运行命令都从项目根目录执行，先激活对应 Conda 环境。路径也从根目录解释：

| 位置 | 放什么 |
| --- | --- |
| `scripts/` | 可运行的练习、训练和推理入口 |
| `src/petvision/` | 可复用的数据、模型、训练和工具函数；新增包目录补 `__init__.py` |
| `tests/` | 检查形状、梯度、Mask、保存加载等行为的测试 |
| `experiments/<主题>/weekN/` | 配置快照、小型指标、图表、环境记录和周总结 |
| `outputs/`、`datasets/` | 权重、大日志和数据，按 `.gitignore` 保留在本地 |

目录树表示逐步要形成的文件。运行命令前，先完成当天指定的函数和入口；尚未创建的脚本按步骤实现。已有文件继续修改，保留此前检查通过的内容。第二周的数据接口会在第三周改成显式传入 transform，回看早期片段时以当前函数签名为准。

代码片段分三种用途：

- 写明文件、类或函数位置的片段，放到指定位置。依赖上文变量的函数体片段要先补齐上下文。
- 手算、小张量和草稿用于理解计算，先预测结果，再运行核对。
- `...`、`pass` 和“自行补齐”是待实现部分。有限参考重写时可以看公式和接口清单，写完后实际调用，再与已有实现比较。

每一步都检查输入的 shape、dtype 和 device，再看输出或梯度。新增测试按指南中的函数名编写，修改时保留已有测试名；数值对照记录实际最大误差、容差和运行模式。形状符号的含义见[总计划约定](StudyPlan.md#reading-conventions)，各周用具体数值再说明。

一个操作步骤应能回答四个问题：改哪个文件或函数，用什么输入，按什么顺序计算，怎样判断结果正确。例如 Mask 的参考对照要实际传入 Mask、复制同一套权重，再比较输出和梯度；只读一遍接口说明还没有完成这项检查。

阅读表用于查资料。接口差异、术语解释和打印要求放在相应操作旁边；有明确手算结果、实现或检查时才单列一步。已有代码时运行该步检查，缺什么补什么，结果沿用本周 README 记录。

## 怎样判断今天做完了

先核对当天“运行与自查”中的输出、断言和样本数，再用自己的话解释计算过程。脚本能跑通与能自己重写分别检查。训练前先做最小前反向和小样本拟合，确认后再扩大预算。

结果写入对应周 README，并链接当次配置、指标和图表。日常可以用口头说明、纸上推导或代码注释检查理解；周末用约 10-20 分钟补充结果、一个遇到的问题和下周要巩固的内容。环境变化时再更新快照。

遇到报错，先停在能复现问题的最小输入，检查形状、标签、设备、梯度和运行模式。比较公式或参考实现时固定输入、权重、Mask 和精度。准确率未达参考值时，先检查流程，再如实分析预算与错误样例；实验结论可以不支持最初的假设。

## 实验之间怎样衔接

MNIST 在第二周配置冻结后测试。CIFAR-10 第三周固定划分并保留测试集，第五周冻结六个变体后统一测试。文本先划分原文再造窗口，第六周只比较验证结果，第七周冻结配置后测试；BPE 规则只用训练原文学习。第八周先写问题和判定标准，再运行 VLM，保留失败记录。

同一对消融保持数据划分、共有初始参数或已说明的初始化方式、增强策略、优化器和预算一致。CNN/ViT 使用 32×32，教材 ResNet 使用 96×96，跨模型表要列出这些条件。字符与 BPE 的 token loss 分别报告。更详细的口径见[实验设计](StudyPlan.md#acceptance)。

总计划和逐日指南保存任务、接口及完成标准，实际进度只在实验 README 中维护。第八周在 `docs/final_report.md` 汇总证据和待补项。完整 Encoder-Decoder、宠物迁移学习、LoRA/QLoRA、VLM 微调和 App 见[后续拓展](StudyPlan.md#extensions)，另行排期。
